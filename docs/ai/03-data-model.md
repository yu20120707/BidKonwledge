# Data Model

## Document

- `id`: string
- `original_filename`: string
- `stored_filename`: string
- `stored_path`: string
- `file_ext`: string
- `content_type`: optional string
- `file_size`: int
- `doc_role`: `historical_bid | tender`
- `created_at`: datetime
- `updated_at`: datetime
- `parse_status`: `pending | parsing | parsed | failed`
- `error_message`: optional string
- `parse_metadata`: dict

Phase 1 only creates documents with `parse_status = pending`.
The original filename is preserved as metadata only; the backend-generated stored filename is the only value used for filesystem persistence.

Phase 8A stores parse metadata such as content-detected format, whether legacy
Word conversion was required, conversion method, and converted relative path.
Absolute local paths must not be stored or returned in API responses.

Phase 8B extends parse metadata for OCR:

- `parse_mode`: `auto | text | ocr`
- `ocr_attempted`: bool
- `ocr_engine`: optional string
- `ocr_pages_count`: optional int
- `ocr_average_confidence`: optional float
- `ocr_fallback_reason`: optional string

OCR metadata may also be copied into chunk metadata for downstream retrieval
and evidence display.

## Section

- `id`: string
- `document_id`: string
- `title`: string
- `level`: int
- `order_index`: int
- `text`: string
- `page_start`: optional int
- `page_end`: optional int

Phase 2 persists parsed sections in SQLite table `document_sections`.

## Chunk

- `id`: string
- `document_id`: string
- `section_id`: string
- `section_title`: string
- `section_path`: string
- `order_index`: int
- `chunk_index`: int
- `chunk_type`: `text`
- `text`: string
- `tags`: list[string]
- `page_start`: optional int
- `page_end`: optional int
- `metadata`: dict

Phase 2 persists chunks in SQLite table `document_chunks`.
Tags are generated by deterministic keyword rules in the minimal parser phase.

For OCR-derived chunks, metadata includes OCR evidence in addition to the
deterministic tagger fields.

## RetrievalRequest

- `query`: optional string
- `tag`: optional string
- `top_k`: int

Phase 3 requires at least one of `query` or `tag`.

## RetrievalResult

- `chunk_id`: string
- `document_id`: string
- `section_id`: string
- `section_title`: string
- `section_path`: string
- `text`: string
- `tags`: list[string]
- `score`: float
- `source`: source metadata object

## RetrievalSourceMetadata

- `original_filename`: string
- `doc_role`: `historical_bid | tender`
- `file_ext`: string
- `page_start`: optional int
- `page_end`: optional int
- `chunk_metadata`: dict

Phase 3 retrieval is deterministic and local. It reads persisted chunks from
SQLite, filters by exact tag, scores simple keyword matches over chunk text and
chunk metadata fields, and does not call LLM, embedding, Qdrant, or Haystack
runtime services.

## KnowledgeCard

- `id`: string
- `document_id`: string
- `source_chunk_id`: string
- `title`: string
- `tag`: string
- `content`: string
- `source_filename`: string
- `source_section_title`: string
- `source_section_path`: string
- `page_start`: optional int
- `page_end`: optional int
- `confidence`: float
- `metadata`: dict
- `created_at`: datetime

Phase 6 persists knowledge cards in SQLite table `knowledge_cards`.
Cards are built deterministically from parsed historical bid chunks and are
replaced on rebuild for the same document. Metadata includes
`tagger = prd_deterministic_v1`, matched keywords, and source chunk metadata.

## ScoringItem

- `name`: string
- `requirement`: string
- `score`: optional float
- `source_text`: string

## RiskItem

- `risk_type`: string
- `description`: string
- `severity`: `low | medium | high`
- `source_text`: optional string

## TenderAnalysis

- `document_id`: string
- `project_requirements`: list[TenderEvidenceItem]
- `scoring_items`: list[TenderEvidenceItem]
- `disqualification_risks`: list[TenderEvidenceItem]
- `raw_text_summary`: string
- `analysis_method`: string
- `need_human_review`: bool
- `metadata`: dict

## TenderEvidenceItem

- `item_id`: string
- `item_type`: `requirement | scoring_item | disqualification_risk`
- `title`: string
- `description`: string
- `source_filename`: string
- `source_chunk_id`: string
- `source_section_title`: string
- `source_section_path`: string
- `page_start`: optional int
- `page_end`: optional int
- `matched_keywords`: list[string]
- `severity`: optional string
- `score`: optional float

Phase 7 persists tender analysis as one latest analysis per `tender` document.
It preserves evidence source fields for each extracted requirement, scoring
item, and disqualification risk. The output is evidence extraction only and
requires human review.

## Citation

- `source_filename`: string
- `source_section_title`: string
- `content_snippet`: string
- `chunk_id`: string
- `document_id`: string

## GenerationResult

- `target_tag`: string
- `generated_content`: string
- `citations`: list[Citation]
- `risks`: list[RiskItem]
- `need_human_review`: bool

Phase 4 generation is candidate content only. `need_human_review` is always
`true`. Automated tests use a fake LLM adapter; real external LLM credentials
are not required for test coverage.

## GenerationLLMConfig

- `api_key`: string
- `base_url`: optional HTTPS URL
- `model`: optional string

This config is accepted on `POST /api/generate` for request-scoped external LLM
calls. It must not be persisted or returned in API responses.
